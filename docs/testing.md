关键断言示例：

- 同一幂等键重复结算返回同一订单，不重复扣库存；
- 支付失败后订单取消且库存恢复；
- 骑手不能操作他人配送单，顾客不能取消他人订单；
- 连续 5 次验证码错误后账号锁定，锁定期内正确验证码也被拒绝；
- 退款被驳回后订单恢复到申请前状态。

## 6. 图形界面冒烟测试

以脚本方式依次登录 5 个演示账号、构建对应主视图并执行一次完整刷新，全部通过：

```
OK CustomerView
OK MerchantView
OK MerchantView
OK RiderView
OK AdminView
```

手工验收路径：

1. 顾客：搜索店铺 → 加购 → 结算（幂等键）→ 模拟支付 → 商家接单/出餐 → 骑手抢单/取餐/送达 → 顾客确认收货并评价。
2. 顾客：售后期申请退款 → 商家同意 → 订单变为“已退款”，支付流水变为“已退款”。
3. 骑手上报异常 → 管理员在“配送调度”重新派单 → 新骑手取餐、送达。
4. 管理员：店铺入驻审核、关停/恢复、退款仲裁、冻结账号、查看审计日志。
5. 定时器每 2 秒执行一次超时检查，状态栏显示本轮处理数量。

报告用界面截图由 `tools/capture_screenshots.py` 自动生成（仅开发期依赖 Pillow）：脚本按 150% 屏幕缩放截取窗口客户区，依次登录顾客、商家、骑手、管理员并切换标签页，输出到 `docs/screenshots/`。共 8 张：登录、顾客点餐、顾客订单、商家订单处理、骑手接单大厅、骑手配送、平台看板、退款仲裁。

## 7. 已知限制

- 数据保存在单进程 JSON 文件中，不支持多客户端并发；服务层已用可重入锁保证单进程一致性。
- 支付与地图均为模拟实现（REQ-024），不接入真实第三方。
- 桌面应用为四端合一，通过账号角色切换视图，而非多机部署。
- GitHub 远程仓库需在具备账号权限的环境中配置；仓库本身不包含任何令牌或凭据。
