# 界面按钮测试与缺陷修复记录

> 本文档单独记录"逐个按钮测试"的过程、用例与修复，不并入实验报告。报告中的测试数据统计截至报告定稿（34 项测试）；本记录对应之后新增的界面测试轮次。

## 1. 测试目标

1. 界面上每个按钮都能被点击并产生明确结果，不出现未捕获异常；
2. 按钮逻辑严谨：未选择行时给出提示，非法输入给出业务提示而非"系统错误"，重复点击不产生错误数据；
3. 界面操作后的服务层数据、状态机状态与提示信息符合预期；
4. 发现问题后修复代码并回归全部测试。

## 2. 测试方法

新增 `tests/test_ui_actions.py`，直接构建真实 Tk 窗口并调用按钮的 `invoke()`，而不是只测服务层。

| 机制 | 做法 |
| --- | --- |
| 数据隔离 | 每个用例使用临时目录 + `Settings(data_dir=...)`，重新建库并写入演示数据 |
| 窗口构建 | 替换 `app.ui.app.build_context` 后实例化 `MainApp`，覆盖登录、主界面、退出登录全链路 |
| 防阻塞 | 用 `unittest.mock` 替换 `messagebox` 与 `simpledialog`；模态对话框的 `show()` 返回预设结果 |
| 异常捕获 | 覆写 `report_callback_exception`，把 Tk 回调中逃逸的异常记为失败；同时把 `showerror("系统错误", ...)` 视为失败 |
| 断言 | 点击后同时检查：无回调异常、无系统错误弹窗、服务层实体状态或统计值已按预期变化 |

运行方式：

```powershell
python -m unittest tests.test_ui_actions -v
```

## 6. 发现的问题与修复

| # | 现象（测试暴露） | 原因 | 修复 |
| ---: | --- | --- | --- |
| 1 | 地址坐标输入"西经三度"弹出"系统错误" | 界面直接 `float()`，`ValueError` 被 `guard` 兜成通用异常 | `widgets.py` 新增 `parse_float`；`_add_address`、`_apply_store` 先校验并提示"坐标必须是数字" |
| 2 | 数量输入非数字导致系统错误 | `IntVar.get()` 在输入非法时抛 `TclError`，无法被业务异常捕获 | 数量变量改为 `StringVar`，用 `parse_int` 校验；购物车与点餐两处一致 |
| 3 | 库存/接单时限输入非数字导致系统错误 | 直接 `int()` 转换 | 新增 `parse_int`，`_add_dish`、`_save_store`、`EditDishDialog._save` 统一友好提示 |
| 4 | 同一秒内先后结算两次，第二笔未生成订单 | 幂等键只精确到秒，第二次点击复用了旧订单 | 每次点击生成 `uuid4` 幂等键；双击仍因购物车已清空而不会重复扣库存 |
| 5 | 设为默认地址后，再点删除无反应 | `_refresh_addresses` 刷新后丢失表格选中行 | 刷新时保存并恢复选中行 |
| 6 | 冻结/解冻、店铺审核后操作目标丢失 | 管理员各表格刷新后未恢复选中行 | `_refresh_stores`、`_refresh_users` 增加选中行恢复 |
| 7 | 未选行点击删除/上架等按钮无任何反馈 | 处理函数直接 `return` | 顾客购物车/地址、商家菜品按钮补充"请先选择…"提示 |
| 8 | 注册流程出现非预期异常时会冒泡到 Tk 回调 | `_do_register` 只捕获 `DomainError` | 补充通用异常分支，统一弹"系统错误"并记录日志 |
| 9 | 重新派单后用 `by_order` 取到的是上一轮失败任务 | 配送仓储按插入顺序返回第一条 | `DeliveryRepository.by_order` 改为按 `dispatch_round` 返回最新任务 |
| 10 | 关闭窗口后偶发 `invalid command name ..._tick` | 定时器 `after` 任务未随窗口销毁取消 | `MainApp` 保存任务 id，`destroy()` 时 `after_cancel` |

说明：第 4、9 项属于业务逻辑缺陷；其余为输入校验、交互反馈或生命周期问题。修复均遵循"先写失败用例复现，再改实现，最后全量回归"的顺序。

## 7. 测试过程中修正的用例问题

以下问题出在测试脚本本身，不是软件缺陷，记录以便复查：

1. 顾客端购物车与地址页都有"删除"按钮，最初按文字查找命中了购物车按钮；改为先在对应标签页容器内查找，避免同名按钮串页。
2. 仲裁通过后的退款状态是 `ARBITRATED`（平台仲裁）而非 `APPROVED`（商家同意），断言已按业务定义区分。
3. 演示店铺默认接单时限是 10 分钟，最初按 15 分钟断言，已改为读取真实初始值。
4. `EditDishDialog` 的保存方法名为 `_save`，最初误写 `_submit`。
5. 关闭窗口时残留的定时器回调会产生 Tcl 背景报错，既修正了 `MainApp` 的生命周期，也在测试中确认不再出现。
