# 从 UML 到代码：设计与实现映射

本文档记录实验二设计（类图、状态图、组件图）如何落到实验三的源码，以及实现过程中对设计的少量调整。实验二的设计材料位于仓库同级的 `lab2` 目录。

## 1. 转换方法

转换按“先骨架、后行为、再界面”的顺序进行，每一步都能独立测试：

1. **类图 → 领域数据类**：类图中的实体类逐一对应 `app/domain/models.py` 中的 `@dataclass`；属性名保持英文；金额统一 `Decimal`，时间统一 `datetime`。
2. **关联与多重性 → 主键引用 / 集合**：一对多关联（店铺—菜品、订单—明细）用“子对象持有父对象 ID + 仓储按 ID 查询”实现，避免对象图循环；组合关系（订单—订单明细）直接保存为列表。
3. **类操作 → 服务方法**：涉及多实体协作、权限、事务的操作放到 `app/services/`，类图上的控制器/服务组件与方法一一对应；只依赖自身状态的行为（库存扣减、可用性判断）保留在领域类上。
4. **状态图 → 显式迁移表**：状态图的所有迁移写成 `app/domain/state_machine.py` 的 `TRANSITIONS` 常量，服务层统一调用 `OrderLifecycle.transition()`；新增状态只改这一张表。
5. **组件图 → 分层与依赖注入**：`ui → services → repository → domain` 单向依赖，`app/container.py` 负责装配，界面与服务不自行创建依赖。
6. **需求编号 → 代码位置**：主要服务方法的文档字符串与提交信息标注 REQ 编号，便于回溯（如 `orders.py` 覆盖 REQ-007/009/018/019）。

## 3. 订单状态机（23 条迁移）

| 当前状态 | 目标状态 | 触发动作 |
| --- | --- | --- |
| 待支付 | 待接单 / 已取消 | 支付成功 / 取消或支付超时 |
| 待接单 | 制作中 / 已取消 | 商家接单 / 拒单、接单超时或顾客取消 |
| 制作中 | 待配送 / 退款中 | 商家出餐 / 申请退款 |
| 待配送 | 配送中 / 退款中 | 骑手取餐 / 无人接单或申请退款 |
| 配送中 | 已送达 / 退款中 / 配送失败 | 确认送达 / 申请退款 / 上报异常 |
| 配送失败 | 配送中 / 退款中 | 平台重新派单 / 判定无法送达 |
| 已送达 | 已完成 / 退款中 | 确认收货或 24h 自动确认 / 售后申请 |
| 退款中 | 已退款 / 已完成 / 已取消 | 退款通过 / 驳回且已送达 / 驳回且未出餐 |
| 退款中 | 制作中/待配送/配送中/配送失败/已送达 | 驳回后恢复申请前状态 |

终态为已完成、已取消、已退款；终态不可再迁移。角色鉴权在服务层完成，状态机只回答“能否迁移”，两者职责分离。

## 4. 数据持久化

- 单一 JSON 文档保存 13 张“表”，写入采用临时文件 + `os.replace` 原子替换。
- 类型编解码器用标记还原非 JSON 类型：`{"__enum__": [...]}`、`{"__decimal__": "..."}`、`{"__datetime__": "..."}`，用户子类用 `_type` 判别。
- 主键由持久化计数器生成（`ORD-0001`、`DLV-0001` 等），重启后不重复。
- 多步业务在同一 `transaction()` 中修改，退出时统一落盘；界面定时器与业务操作共享可重入锁。

## 5. 对实验二设计的调整

| 调整 | 原因 |
| --- | --- |
| 新增 `OrderLifecycle` 统一状态迁移、库存释放与通知 | 避免订单/配送/退款服务相互依赖形成环 |
| 新增 `jobs/scheduler.py` | 将超时兜底从界面定时器中剥离，命令行与界面共用 |
| `DeliveryTask` 独立于 `Order` | 配送失败后需要保留旧任务并创建新任务 |
| `RefundRequest` 保存 `status_before_refund` | 驳回退款时要精确恢复订单原状态 |
| 店铺增加 `accept_timeout_minutes` | REQ-019 要求接单时限可配置并限制在 5–20 分钟 |
| 界面为四端合一的单进程桌面应用 | 实验三要求桌面应用，便于后续分析与测试 |

## 7. 可扩展点

- **换数据库**：实现与 `Repository` 同名的方法即可替换 `JsonDatabase`，服务层无感知。
- **新增订单状态**：在 `OrderStatus` 与 `TRANSITIONS` 增加枚举和迁移，服务层通过 `OrderLifecycle` 自动获得校验与审计。
- **新增角色端**：继承 `BaseView`，在 `MainApp._build_role_view` 注册即可。
- **接入真实支付/地图**：`PaymentService` 与 `pricing.distance_km` 是唯一改动点。
- **新增定时规则**：在 `Scheduler.tick()` 增加处理步骤，沿用 `_safely` 隔离异常。
